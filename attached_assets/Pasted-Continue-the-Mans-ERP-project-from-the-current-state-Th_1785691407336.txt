Continue the Mans ERP project from the current state.

The project is already running correctly. Do NOT modify infrastructure, authentication, database setup, Docker, Prisma configuration, Clerk configuration, workflows, or existing RBAC architecture unless absolutely required by the task.

## Goal
Implement a complete User & Role Management module that integrates with the existing RBAC system.

## Existing Architecture
- React + TypeScript frontend
- Express + Prisma backend
- PostgreSQL
- Clerk authentication
- Existing RBAC (roles, permissions, role_permissions, user_roles)
- Existing audit log system
- Existing organization scoping
- Existing translation system (Arabic + English)

Reuse existing components, patterns, hooks, utilities and API style wherever possible.

---

# Phase 1 — Users Management

Create a complete Users Management page.

Features:

- List users
- Search by:
  - Name
  - Email
  - Role
- Filter by:
  - Active
  - Disabled
- Pagination
- User details page
- Status badges
- Last login (if available)
- Created date
- Organization

Actions:

- Activate user
- Deactivate user
- View details

Never allow deleting users.

Only Super Admin and Organization Admin may access these pages.

---

# Phase 2 — Role Assignment

Allow admins to:

- Assign role
- Change role
- Remove role

Requirements:

- Use existing RBAC tables.
- Do NOT duplicate permissions.
- Preserve organization boundaries.
- Audit every role change.

Prevent:

- Removing your own last admin role.
- Removing the last Organization Admin of an organization.
- Removing the last Super Admin in the system.

---

# Phase 3 — Invitation System

Implement an invitation workflow instead of automatic role assignment.

Features:

- Invite user by email.
- Select role before sending invite.
- Invitation expires after configurable period.
- Accept invitation after Clerk authentication.
- Reject expired invitations.
- Prevent duplicate active invitations.
- Prevent inviting users already in the organization.

Create a proper Prisma model and migration only if one does not already exist.

Audit:

- Invitation created
- Accepted
- Revoked
- Expired

---

# Phase 4 — Security

Verify every endpoint.

No endpoint may rely only on frontend visibility.

Every backend route must enforce:

- Authentication
- Organization scope
- RBAC permission

Return proper HTTP status codes.

403 for insufficient permissions.
404 for inaccessible resources.
409 for conflicts.
422 for validation.
400 only for malformed requests.
